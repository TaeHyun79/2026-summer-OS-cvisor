# 이 프로젝트의 x86-64 어셈블리 문법 노트

`tests/hello.s`와 `ch6/swtch.s`에 **실제로 등장하는** 문법·지시자·규약만 모았습니다.
[C 문법 노트](c-syntax-notes.md)와 같은 방식이고, 각 항목의 `파일:줄`은 실제 사용
위치입니다.

두 파일 모두 **GNU as(GAS)의 AT&T 문법**, **x86-64**, **libc 없음**입니다.

---

## 1. AT&T 문법 — Intel 문법과 뭐가 다른가

인터넷 자료와 Intel 매뉴얼은 Intel 문법이고, 리눅스 커널·GCC 출력·이 프로젝트는
AT&T 문법입니다. **네 가지가 다릅니다.**

| | AT&T (GAS, 이 프로젝트) | Intel (NASM, MASM) |
|---|---|---|
| 피연산자 순서 | `movq %rsp, 8(%rdi)` — **출발지 먼저** | `mov [rdi+8], rsp` — 목적지 먼저 |
| 레지스터 | `%rax` | `rax` |
| 즉시값 | `$60` | `60` |
| 메모리 | `8(%rdi)` | `[rdi+8]` |
| 크기 표시 | 명령 접미사 `movq` | 피연산자 `qword ptr` |

**피연산자 순서가 뒤집힌 것**이 가장 큰 함정입니다. 읽는 요령은 왼쪽에서
오른쪽으로 화살표를 그리는 것입니다:

```asm
movq    %rsp,  8(%rdi)      # %rsp  ->  [%rdi + 8]      (저장)
movq    8(%rsi), %rsp       # [%rsi + 8]  ->  %rsp      (적재)
```

`ch6/swtch.s:80`과 `:95`가 정확히 이 대칭 관계입니다 — 하나는 컨텍스트에 저장,
하나는 컨텍스트에서 복원.

`$`와 `%`가 붙는 이유도 여기 있습니다. `movq $1, %rax`는 "상수 1을 rax에",
`movq 1, %rax`는 "**주소 1번지의 값**을 rax에"로 완전히 다른 뜻입니다. `$`를
빼먹는 것이 초보자의 대표적 버그입니다.

## 2. 레지스터

### 범용 레지스터 16개

x86-64에는 64비트 범용 레지스터가 16개 있습니다.

```
%rax %rbx %rcx %rdx %rsi %rdi %rbp %rsp        (8086부터 이어진 8개)
%r8  %r9  %r10 %r11 %r12 %r13 %r14 %r15        (x86-64에서 추가된 8개)
```

이름이 규칙적이지 않은 앞의 8개는 역사적 유래가 있습니다 — **A**ccumulator,
**B**ase, **C**ounter, **D**ata, **S**ource **I**ndex, **D**estination **I**ndex,
**B**ase **P**ointer, **S**tack **P**ointer. 지금은 `%rsp`를 빼면 대부분 범용으로
쓰이지만, 일부 명령이 특정 레지스터를 암묵적으로 씁니다.

### 부분 레지스터 — 같은 물리 레지스터의 다른 창

하나의 레지스터를 폭을 달리해 접근할 수 있습니다.

| 64비트 | 32비트 | 16비트 | 8비트 |
|---|---|---|---|
| `%rax` | `%eax` | `%ax` | `%al` |
| `%rdi` | `%edi` | `%di` | `%dil` |
| `%r12` | `%r12d` | `%r12w` | `%r12b` |

**중요한 규칙**: 32비트 레지스터에 쓰면 **상위 32비트가 자동으로 0이 됩니다.**
16비트·8비트에 쓸 때는 나머지가 보존됩니다. 이 비대칭 때문에

```asm
movq    $3, %rbx        # 7바이트 (48 c7 c3 03 00 00 00)
movl    $3, %ebx        # 5바이트 (bb 03 00 00 00) — 결과는 동일
```

두 줄의 **결과가 같습니다**. 컴파일러 출력에 `xorq %rax, %rax`(3바이트,
`48 31 c0`) 대신 `xorl %eax, %eax`(**2바이트**, `31 c0`)가 거의 항상 나오는
것도 같은 이유입니다.

### 특수 목적

| 레지스터 | 역할 |
|---|---|
| `%rsp` | 스택 포인터. `push`/`pop`/`call`/`ret`이 암묵적으로 수정 |
| `%rbp` | 프레임 포인터 (관례일 뿐, 강제 아님) |
| `%rip` | 명령 포인터. **직접 읽고 쓸 수 없고**, 주소 지정에만 등장 |
| `EFLAGS` | 비교 결과 플래그. 이름으로 접근 불가, 조건 분기가 읽음 |

`%rip`을 `movq %rip, %rax`처럼 쓸 수 없다는 점이 중요합니다. 현재 주소를 얻으려면
`leaq 0(%rip), %rax` 같은 형태를 씁니다.

## 3. 피연산자 세 종류

### 즉시값 (immediate)

```asm
movq    $3, %rbx            # ch6/swtch.s:119
movq    $60, %rax           # :133  — sys_exit 번호
movq    $msg_a_len, %rdx    # :123  — 심볼도 상수면 $ 를 붙임
```

`$` + 숫자 또는 심볼. `.set`으로 만든 절대 심볼(4절)은 상수이므로 `$`가 붙습니다.

### 레지스터

```asm
movq    %rsp, 8(%rdi)
```

### 메모리 — 완전한 형태

```
변위(베이스, 인덱스, 스케일)     ->   변위 + 베이스 + 인덱스 × 스케일
disp(%base, %index, scale)
```

`scale`은 1, 2, 4, 8만 가능합니다. 실제 사용되는 축약형들:

```asm
(%rdi)              # [%rdi]                    swtch.s:79
8(%rdi)             # [%rdi + 8]                swtch.s:80
56(%rsi)            # [%rsi + 56]               swtch.s:89
msg(%rip)           # RIP 상대 (아래 4절)       hello.s:22
```

배열 접근이라면 `(%rax, %rcx, 8)` = `[rax + rcx*8]` 형태를 쓰지만, 이 프로젝트의
두 파일에는 등장하지 않습니다.

> **`8(%rdi)`의 `8`은 바이트 단위**입니다. `struct context`의 필드 오프셋이
> `0, 8, 16, 24, ...`로 나가는 이유가 그것입니다 — 전부 `uint64_t`라 8바이트씩.

## 4. RIP 상대 주소 지정 — 왜 어디에나 있는가

```asm
leaq    msg_a(%rip), %rsi           # ch6/swtch.s:122
movq    %rax, ctx_b+0(%rip)         # :114
incq    counter(%rip)               # tests/hello.s:26
```

`심볼(%rip)`은 "**현재 명령의 다음 주소 + 오프셋**"을 뜻합니다. 어셈블러가 오프셋을
계산해 넣어주므로 소스에는 심볼 이름만 씁니다.

실제로 인코딩된 걸 보면:

```
40104e: 48 8d 05 53 00 00 00    lea 0x53(%rip),%rax    # 4010a8 <thread_b>
```

`0x53`이 오프셋이고, 기준은 다음 명령 주소 `0x401055`입니다.
`0x401055 + 0x53 = 0x4010a8` = `thread_b`. objdump가 오른쪽에 계산 결과를
주석으로 달아줍니다.

**왜 절대 주소 대신 이걸 쓰는가**:

1. **PIE/PIC 지원** — 로드 주소가 바뀌어도 명령과 데이터의 *상대* 거리는 그대로라
   재배치(relocation)가 필요 없습니다. 요즘 배포판이 기본 PIE인 이유로 GCC가
   거의 항상 이 형태를 냅니다.
2. **인코딩이 짧다** — 64비트 절대 주소는 8바이트지만 RIP 상대는 4바이트 변위로
   ±2GB를 커버합니다.

x86-64에서 새로 생긴 주소 지정 방식입니다. i386에는 없어서, 32비트 PIC 코드는
`call`/`pop` 트릭으로 현재 주소를 얻어야 했습니다.

> 이 프로젝트는 `-no-pie`(ET_EXEC)로 링크하므로 절대 주소를 써도 되지만,
> RIP 상대가 짧고 관례적이라 그대로 씁니다. cvisor가 PIE를 거부하는
> 이유(`analyzer.c:55-62`)는 objdump 주소와 런타임 주소를 일치시키기 위해서지
> RIP 상대와는 무관합니다.

## 5. 명령어 접미사 — `q`, `l`, `w`, `b`

```asm
movq    # quad word  = 8바이트 (64비트)
movl    # long       = 4바이트 (32비트)
movw    # word       = 2바이트 (16비트)
movb    # byte       = 1바이트
```

`word`가 2바이트인 건 8086의 레지스터 폭이 16비트였던 유산입니다.

**언제 필수인가**: 피연산자만으로 크기를 알 수 없을 때입니다.

```asm
incq    counter(%rip)       # 필수 — 메모리 피연산자뿐이라 크기 정보가 없음
movq    %rsp, 8(%rdi)       # 생략 가능 — %rsp가 64비트임이 자명
```

`hello.s:26`의 `incq`에서 `q`를 빼면 **에러가 아니라 경고**가 나고, GAS가
멋대로 기본값을 고릅니다:

```
Warning: no instruction mnemonic suffix given and no register operands;
         using default for `inc'
   0:  ff 05 00 00 00 00    incl   0x0(%rip)
```

`incq`가 아니라 **`incl`(32비트)** 이 됐습니다. 8바이트 카운터를 4바이트만
증가시키게 되므로, 조용히 틀리는 쪽이라 에러보다 위험합니다. 메모리 전용
연산에는 반드시 접미사를 붙이세요.

반면 레지스터가 하나라도 있으면 크기가 자명하므로 `mov`로 써도 됩니다.

objdump 출력에는 접미사가 대부분 안 붙어 보입니다 (`mov %rsp,0x8(%rdi)`) —
레지스터로 크기를 알 수 있어서고, 필요할 때만 `incq`처럼 붙여줍니다.

## 6. GAS 지시자 (directive)

`.`으로 시작하는 것은 **명령어가 아니라 어셈블러에 대한 지시**입니다. 기계어를
만들지 않거나(`.globl`), 데이터를 배치합니다(`.quad`).

### 섹션 선택

```asm
        .section .rodata        # ch6/swtch.s:48  — 읽기 전용 데이터
        .section .data          # :54  — 초기값 있는 쓰기 가능 데이터
        .section .bss           # :62  — 0으로 시작하는 데이터 (파일에 자리 안 씀)
        .text                   # :68  — 코드 (.section .text 의 축약)
```

이후 나오는 내용이 그 섹션에 쌓입니다. 섹션은 여러 번 오갈 수 있고, 어셈블러가
같은 이름끼리 모아줍니다.

**`.data`와 `.bss`의 차이**가 실물로 드러납니다:

```asm
ctx_a:  .quad   0, 0, 0, 0, 0, 0, 0, 0      # .data — 64바이트가 파일에 실제로 들어감
b_stack:
        .space  4096                        # .bss — 크기만 기록, 파일 크기 0
```

`.bss`는 "이만큼을 0으로 채워 달라"는 요청만 ELF에 남기므로 4096바이트짜리
스택을 잡아도 바이너리가 커지지 않습니다. `tests/globals.c`가 C에서 보여주는 것과
같은 구분입니다.

> `.rodata`는 cvisor의 globals 패널에 **안 나옵니다**. `analyzer.c:82-88`이
> `.data`와 `.bss`만 보기 때문입니다.

### 데이터 정의

| 지시자 | 크기 | 사용처 |
|---|---|---|
| `.byte` | 1 | |
| `.word` | 2 | |
| `.long` | 4 | |
| `.quad` | 8 | `swtch.s:57` — struct context 필드 |
| `.ascii "..."` | 문자열, **NUL 없음** | `swtch.s:49` |
| `.asciz` / `.string` | 문자열 + NUL | (이 프로젝트엔 없음) |
| `.space N` / `.skip N` | N바이트 0 | `swtch.s:65` — B의 스택 |

```asm
ctx_a:  .quad   0, 0, 0, 0, 0, 0, 0, 0      # 쉼표로 여러 개를 한 줄에
```

`.ascii`를 쓴 이유는 `write(2)`에 길이를 직접 넘기기 때문입니다 — NUL 종료가
필요 없고, 오히려 있으면 출력에 섞입니다. C 문자열이 필요하면 `.asciz`를 씁니다.

### 정렬

```asm
        .balign 8               # ch6/swtch.s:55  — 다음 위치를 8의 배수로
        .balign 16              # :63
```

패딩을 넣어 다음 항목의 주소를 맞춥니다. `.align`도 있지만 **아키텍처마다 의미가
달라**(어떤 곳은 바이트 수, 어떤 곳은 2의 지수) `.balign`(= byte align)이 항상
바이트 수라 안전합니다.

8바이트 정렬이 필요한 이유는 `.quad` 접근이 정렬돼야 빠르고(일부 명령은 필수),
스택은 SysV ABI가 16바이트 정렬을 요구하기 때문입니다.

### 심볼 정의

```asm
        .globl  _start          # ch6/swtch.s:112  — 링커에 심볼 노출
        .set    msg_a_len, . - msg_a    # :50  — 상수 심볼 정의
```

`.globl`(= `.global`)은 C의 `extern` 반대편입니다 — 이 심볼을 다른 오브젝트
파일에서 볼 수 있게 합니다. `_start`에 필요한 이유는 **링커가 기본 진입점으로
`_start`라는 전역 심볼을 찾기** 때문입니다. 빼면 에러가 아니라 경고가 나고,
진입점이 `.text`의 시작 주소로 정해집니다:

```
ld: warning: cannot find entry symbol _start; defaulting to 0000000000401000
```

`_start`가 마침 `.text` 맨 앞이면 우연히 동작하지만, 앞에 다른 함수가 있으면
그것이 실행됩니다.

`.set NAME, expr`(= `.equ`)은 값을 계산해 심볼에 묶습니다. 주소가 아니라 **절대
상수**가 되고, 실제로 심볼 테이블에서 `ABS`로 확인됩니다:

```
     3: 000000000000000a     0 NOTYPE  LOCAL  DEFAULT  ABS msg_a_len
```

`0x0a` = 10 = `"A running\n"`의 길이입니다.

## 7. 라벨과 위치 카운터

### 라벨

```asm
swtch:              # ch6/swtch.s:77
put:                # :103
_start:             # :113
.La_loop:           # :121
```

`이름:`은 "이 위치의 주소에 이 이름을 붙여라"입니다. 코드든 데이터든 동일합니다.

### `.L` 접두사 = 지역 라벨

`.L`로 시작하는 라벨은 **오브젝트 파일의 심볼 테이블에 남지 않습니다.**
확인해보면:

```
$ nm ch6/swtch
0000000000401000 T swtch
000000000040103d t put
000000000040104e T _start
00000000004010a8 t thread_b
...
```

`.La_loop`, `.Lb_loop`는 아예 없습니다. 반면 `.globl`을 안 붙인 `put`,
`thread_b`는 **소문자 `t`(지역 심볼)로 남아 있습니다.**

| nm 기호 | 뜻 |
|---|---|
| `T` / `t` | `.text` — 대문자 = 전역, 소문자 = 지역 |
| `D` / `d` | `.data` |
| `B` / `b` | `.bss` |
| `r` | `.rodata` |
| `a` | 절대 심볼 (`.set`으로 만든 것) |

실용적 차이: 심볼 테이블에 남으면 **objdump가 디스어셈블리에 `<put>:` 라벨을
찍어주고**, cvisor의 disassembly 패널에도 그 라벨이 보입니다(`dline_t.is_label`,
`cvisor.h:37`). 루프 라벨까지 전부 남으면 패널이 지저분해지므로, 내부 분기
대상은 `.L`을 붙이는 것이 관례입니다.

> GCC가 만든 어셈블리에 `.L2`, `.L3` 같은 게 잔뜩 보이는 이유가 이것입니다.

### 위치 카운터 `.`

`.`(점 하나)은 **현재 주소**를 뜻하는 특수 심볼입니다.

```asm
msg_a:  .ascii  "A running\n"
        .set    msg_a_len, . - msg_a        # ch6/swtch.s:49-50
```

`.ascii` 다음의 `.`은 문자열 끝 주소이므로, `. - msg_a`가 곧 **길이**입니다.
문자열을 고쳐도 길이가 자동으로 따라오므로 `10`을 손으로 세어 넣는 것보다
안전합니다. C의 `sizeof(arr)/sizeof(arr[0])` 관용구와 같은 발상입니다.

## 8. 주석

```asm
# 한 줄 주석 (x86 GAS)         — xv6 원본 스타일
/* 블록 주석 */                 — 여러 줄 가능
```

x86에서는 `#`가 주석이지만 **아키텍처마다 다릅니다** (ARM은 `//`와 `@`, 일부는
`;`). `/* */`는 어디서나 통하고 여러 줄에 걸칠 수 있어 파일 헤더에 적합합니다.

이 프로젝트는 파일·섹션 헤더에 `/* */`, 명령 옆 설명에 `#`를 씁니다
(`ch6/swtch.s`가 xv6 원본의 `#` 스타일을 유지).

> `.s`(소문자)는 전처리기를 거치지 않고, `.S`(대문자)는 gcc가 C 전처리기를
> 돌립니다. `.S`에서는 `#`가 `#include`/`#define`과 충돌하므로 `//`나 `/* */`를
> 써야 합니다. 이 프로젝트는 전부 `.s`입니다.

## 9. SysV AMD64 호출 규약

어셈블리에서 함수를 만들고 부르려면 **규약을 손으로 지켜야** 합니다. 리눅스
x86-64의 규약은 다음과 같습니다.

### 인자와 반환값

| 용도 | 레지스터 |
|---|---|
| 정수/포인터 인자 1~6 | `%rdi`, `%rsi`, `%rdx`, `%rcx`, `%r8`, `%r9` |
| 7번째 이후 | 스택 (오른쪽부터 push) |
| 반환값 | `%rax` (128비트면 `%rdx:%rax`) |

```asm
        leaq    ctx_a(%rip), %rdi       # 1번 인자: old
        leaq    ctx_b(%rip), %rsi       # 2번 인자: new
        call    swtch                   # ch6/swtch.s:126-128
```

`void swtch(struct context *old, struct context *new)`의 호출이 이렇게 됩니다.
i386은 두 인자를 모두 스택에 넣었기 때문에 xv6 원본이 `movl 4(%esp), %eax`로
꺼내야 했습니다 — x86-64에서는 이미 레지스터에 있어 그 단계가 사라집니다.

### caller-saved vs callee-saved

**이것이 `swtch`의 존재 이유 자체**입니다.

| 구분 | 레지스터 | 규칙 |
|---|---|---|
| **callee-saved** (피호출자 보존) | `%rbx`, `%rbp`, `%r12`~`%r15` | 함수가 쓰려면 저장 후 복원해야 함 |
| **caller-saved** (호출자 보존) | `%rax`, `%rcx`, `%rdx`, `%rsi`, `%rdi`, `%r8`~`%r11` | 함수가 마음대로 망가뜨려도 됨 |

`struct context`에 정확히 `%rbx`, `%rbp`, `%r12`~`%r15`만 들어 있는 이유가
여기 있습니다 — **caller-saved 레지스터는 어차피 `call` 시점에 살아있지 않다고
가정되므로 저장할 필요가 없습니다.**

i386의 callee-saved는 `ebx`, `esi`, `edi`, `ebp`인데, x86-64에서 `esi`/`edi`는
**인자 레지스터가 되면서 caller-saved로 바뀌었습니다.** 그래서 포팅할 때
컨텍스트에서 빠진 것입니다.

`ch6/swtch.s:103`의 `put`이 `%rax`/`%rdi`/`%rcx`/`%r11`을 망가뜨리면서도
안전한 것도 같은 이유입니다 — 전부 caller-saved입니다.

### 스택 정렬과 레드 존

- **`call` 직전에 `%rsp`가 16바이트 정렬**이어야 합니다. SSE 명령이 정렬된
  스택을 가정하기 때문인데, libc를 부르지 않는 이 프로젝트에서는 위반해도
  실제 문제가 생기지 않습니다.
- **레드 존(red zone)**: `%rsp` 아래 **128바이트**는 시그널 핸들러조차 건드리지
  않는다고 보장됩니다. leaf 함수가 `%rsp`를 조정하지 않고 임시 공간으로 쓸 수
  있습니다.

> cvisor의 `CV_STACK_RED_ZONE`(`cvisor.h:21`)은 64로 정의돼 있는데, 이는 ABI의
> 128바이트 레드 존과는 별개로 "RSP 아래 몇 바이트까지 스냅샷할지" 정한 값입니다.
> 이름만 같은 개념을 빌려온 것입니다.

## 10. 시스템 콜 규약 (호출 규약과 다름!)

```asm
        movq    $1, %rax        # 시스템 콜 번호 (sys_write)
        movq    $1, %rdi        # 인자 1
                                # %rsi, %rdx 는 호출자가 이미 채움
        syscall                 # ch6/swtch.s:104-106
```

| 항목 | 함수 호출 | 시스템 콜 |
|---|---|---|
| 번호/대상 | `call 주소` | `%rax`에 번호, `syscall` |
| 인자 4번째 | `%rcx` | **`%r10`** ← 다름! |
| 반환 | `%rax` | `%rax` (음수면 `-errno`) |
| 파괴되는 것 | caller-saved 전부 | **`%rcx`, `%r11`만** |

**4번째 인자가 `%rcx`가 아니라 `%r10`인 이유**가 그 아래 줄에 있습니다:
`syscall` 명령은 복귀 주소를 `%rcx`에, RFLAGS를 `%r11`에 하드웨어적으로
저장합니다. 그래서 `%rcx`를 인자로 쓸 수 없습니다.

이건 추측이 아니라 트레이스에서 직접 보입니다:

```
step 11 | ret | RAX 1->a | RCX 0->40104d | R11 0->302
```

`0x40104d`는 `syscall` 바로 다음 명령의 주소입니다 (`ch6/swtch.s:107`의 `ret`).

주요 번호 (`src/trace.c:40`의 `SC_NAMES[]`가 같은 표):

| 번호 | 이름 |
|---|---|
| 0 | `read` |
| 1 | `write` |
| 60 | `exit` |
| 231 | `exit_group` |

`_start`에서 `ret`하면 돌아갈 곳이 없어 SIGSEGV이므로, **libc 없는 프로그램은
반드시 `exit` 시스템 콜로 끝내야** 합니다 (`ch6/swtch.s:133-135`).

## 11. 스택과 `call`/`ret`

### 스택은 아래로 자란다

`%rsp`는 **낮은 주소 방향으로** 이동합니다.

```asm
pushq   %rax        # %rsp -= 8, 그 다음 [%rsp] = %rax
popq    %rax        # %rax = [%rsp], 그 다음 %rsp += 8
```

`push`가 먼저 감소하고 쓰므로, `%rsp`는 항상 **가장 최근에 밀어 넣은 값**을
가리킵니다.

cvisor의 stack 패널에서 `d` 키로 방향을 뒤집을 수 있는 것(`tui.c:713`,
`stack_desc`)이 이 때문입니다 — 높은 주소를 위에 두는 CSAPP 관례와 낮은 주소를
위에 두는 hex dump 관례가 둘 다 쓰입니다.

### `push`/`pop`은 메모리도 받는다

```asm
        popq    0(%rdi)         # ch6/swtch.s:79
        pushq   0(%rsi)         # :96
```

레지스터뿐 아니라 메모리 위치를 직접 대상으로 삼을 수 있습니다. `swtch`가
복귀 주소를 임시 레지스터를 거치지 않고 곧장 컨텍스트에 저장/복원하는 방식이
이것입니다.

### `call`과 `ret`

```
call 주소   ≡   pushq (다음 명령의 주소) ; jmp 주소
ret         ≡   popq  %rip
```

즉 `call`은 **복귀 주소를 스택에 밀어 넣는 점프**이고, `ret`은 **스택에서 꺼낸
주소로 점프**합니다. 별도의 "복귀 주소 레지스터"가 없습니다 (ARM의 `lr`과 대비).

이 사실이 `swtch`의 핵심 트릭을 만듭니다:

```asm
        movq     8(%rsi), %rsp  # stack is switched here   :95
        pushq    0(%rsi)        # return addr put in place :96
        ret                     # finally return into new ctxt :97
```

`%rsp`를 새 스레드의 스택으로 바꾼 뒤, 새 스레드의 저장된 RIP를 그 스택에 밀어
넣고 `ret`합니다. **`ret`이 "복귀"가 아니라 "임의의 주소로 점프"하는 도구로
쓰인 것**입니다. 트레이스에서 그 순간이 이렇게 보입니다:

```
step 31 | rip=0x40103c | swtch.s:97 | ret
step 32 | rip=0x4010a8 | swtch.s:144 | inc %r12      <- thread_b 로 착지
```

## 12. 제어 흐름과 FLAGS

### 조건 분기는 두 단계

x86에는 "비교해서 바로 분기"하는 명령이 없습니다. **연산이 FLAGS를 설정하고,
분기 명령이 그것을 읽습니다.**

```asm
        decq    %rbx            # 결과에 따라 ZF/SF/OF 갱신
        jnz     .La_loop        # ZF == 0 이면 점프   ch6/swtch.s:130-131
```

`decq`가 3이 아니라 2를 만들면 ZF=0 → 점프, 0을 만들면 ZF=1 → 통과.
`cmp`나 `test`를 따로 쓰지 않은 것은 `dec`가 이미 플래그를 갱신하기 때문입니다.

주요 플래그 (cvisor의 registers 패널 마지막 줄, `tui.c:172`의 `FLAG_BITS[]`):

| 플래그 | 비트 | 뜻 |
|---|---|---|
| CF | 0 | 부호 없는 자리올림/빌림 |
| PF | 2 | 하위 8비트의 1 개수가 짝수 |
| ZF | 6 | 결과가 0 |
| SF | 7 | 결과가 음수 (최상위 비트) |
| OF | 11 | 부호 있는 오버플로 |

트레이스의 `FLG 206->246`은 `decq`가 `%rbx`를 0으로 만들어 ZF(비트 6, 0x40)가
켜진 것입니다.

### 조건 분기 이름

| 명령 | 조건 | 별칭 |
|---|---|---|
| `je` / `jz` | ZF=1 | equal / zero |
| `jne` / `jnz` | ZF=0 | not equal / not zero |
| `jl` / `jge` | 부호 있는 비교 | less / greater-or-equal |
| `jb` / `jae` | 부호 없는 비교 | below / above-or-equal |

**`jl`(signed)과 `jb`(unsigned)를 구분하는 것**이 중요합니다. 같은 비트 패턴도
부호 해석에 따라 대소가 뒤집힙니다.

> `jnz`와 `jne`는 **완전히 같은 명령**입니다. 인코딩이 동일하고 이름만
> 두 개입니다. objdump는 `jne`로 출력하므로, `ch6/swtch.s:131`에 `jnz`라고
> 써도 디스어셈블리에는 `jne`로 나타납니다.

## 13. 명령어 인코딩 — 왜 주소 간격이 들쭉날쭉한가

x86-64는 **가변 길이** 명령어입니다. 1바이트부터 15바이트까지.

```
[프리픽스] [REX] [옵코드] [ModRM] [SIB] [변위] [즉시값]
   0~4      0~1    1~3      0~1    0~1  0/1/2/4  0/1/2/4/8
```

실제 예:

| 바이트 | 길이 | 명령 |
|---|---|---|
| `c3` | 1 | `ret` |
| `0f 05` | 2 | `syscall` |
| `75 d5` | 2 | `jne`(단거리, 8비트 변위) |
| `48 ff cb` | 3 | `dec %rbx` |
| `48 89 67 08` | 4 | `mov %rsp,0x8(%rdi)` |
| `e8 b9 ff ff ff` | 5 | `call`(32비트 상대 변위) |
| `48 c7 c3 03 00 00 00` | 7 | `mov $0x3,%rbx` |

`48`이 **REX.W 접두사**입니다 — "이 연산은 64비트"라는 표시로, x86-64에서
새로 생겼습니다. `%r8`~`%r15`를 쓰면 확장 비트가 켜져 `4c` 등이 됩니다
(길이는 그대로).

**결과**: 디스어셈블리에서 `주소 간격 = 앞 명령의 바이트 수`입니다. `swtch` 본체가
4씩 규칙적으로 늘어난 건 같은 형태의 `mov`가 반복돼서지 우연이 아닙니다.

**대가**: 명령 경계를 알려면 **처음부터 순차적으로 디코딩**해야 합니다. 임의의
주소가 명령 시작인지 알 방법이 없습니다. ARM64는 모든 명령이 정확히 4바이트라
이 문제가 없습니다.

이 성질이 cvisor 코드에 직접 반영돼 있습니다:

```c
/* exact binary search over irefs (rip is always an instruction boundary) */
int32_t trace_insn_lookup(const trace_t *t, uint64_t rip)   /* trace.c:63 */
```

주소에서 인덱스를 계산할 수 없으니 objdump가 준 주소 목록을 이진 탐색해야
합니다. ARM64였다면 `(rip - text_start) / 4`로 끝났을 일입니다.

반대로 `syscall`이 `0f 05` 2바이트 고정이라는 점은 활용됩니다:

```c
uint8_t op[2];
if (read_mem(&c, regs.rip, op, 2) == 2 && op[0] == 0x0f && op[1] == 0x05)
                                                    /* recorder.c:352-356 */
```

## 14. 빌드

```sh
as -g -o hello.o hello.s      # 어셈블 (-g = DWARF 줄 정보 생성)
ld -o hello hello.o           # 링크 (libc 없음)
```

Makefile의 `tests/%: tests/%.s`와 `ch6/%: ch6/%.s` 규칙이 이것입니다.

**`as -g`가 필수인 이유**: cvisor는 DWARF 줄 정보가 없으면 시작을 거부합니다
(`analyzer.c:356`). `-g`를 주면 GAS가 **`.s` 파일 자체를 컴파일 단위로 하는**
`.debug_line`을 만들어주므로, 소스 패널에 어셈블리가 그대로 뜹니다.

**`ld`를 직접 쓰는 이유**: `gcc`로 링크하면 `crt1.o`(그 안의 `_start`가
`main`을 부름)와 libc가 딸려옵니다. `ld`는 그냥 `_start`를 진입점으로 삼습니다.
`gcc -nostdlib -no-pie`도 동등하지만, `ld` 기본 출력이 이미 ET_EXEC라
`-no-pie`에 해당하는 옵션이 필요 없습니다.

확인 명령:

```sh
objdump -d <바이너리>                    # 기계어 바이트 포함 디스어셈블
objdump -d --no-show-raw-insn <바이너리>  # cvisor가 실제로 쓰는 형태
objdump --dwarf=decodedline <바이너리>    # 줄 테이블 (없으면 cvisor가 거부)
nm <바이너리>                            # 심볼 테이블
readelf -S <바이너리>                    # 섹션 목록
```

## 부록: 자주 하는 실수

| 실수 | 증상 |
|---|---|
| 피연산자 순서를 Intel식으로 씀 | 조용히 반대로 동작 (`mov`는 양방향 다 유효) |
| 즉시값에 `$` 누락 | 상수 대신 그 주소의 메모리를 읽음 |
| 메모리 전용 연산에 접미사 누락 | 경고만 뜨고 `l`(32비트)로 조용히 처리됨 |
| 시스템 콜 4번째 인자를 `%rcx`에 | `syscall`이 `%rcx`를 덮어씀 → 엉뚱한 값 |
| callee-saved를 저장 없이 사용 | 호출한 쪽이 값을 잃음 (디버깅 지옥) |
| `_start`에서 `ret` | SIGSEGV — `exit` 시스템 콜로 끝내야 함 |
| `.globl _start` 누락 | 경고 후 진입점이 `.text` 시작 주소로 정해짐 |
| `.ascii`를 C 문자열처럼 사용 | NUL이 없어 출력이 이어짐 (`.asciz` 필요) |
| `as`에 `-g` 누락 | cvisor가 `no DWARF line info`로 거부 |
